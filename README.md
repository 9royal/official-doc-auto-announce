# 公文自動公告系統 布建說明

把公文丟進 Google 雲端硬碟的資料夾，AI 會自動整理成校網公告草稿、檢查個資。你在「審核台」按核准後，Chrome 裡的「公告助手」會自動發到學校網站（黑快馬 R-page 公告模組），連公文本體和附件一起上傳。需要的話，也可以照學校規範的標題格式，寄信給校內群組。

每則公文三選一：**公告＋寄信**、**只有公告**、**只有寄信**。

版本：系統 v10.1、公告助手 1.8、寄信小幫手 1.1。公告部分安裝約 30 分鐘，寄信部分（選用）再約 15 分鐘。

## 運作方式

1. **放公文**：把公文和附件丟進雲端硬碟「公文自動公告 / 00_待處理」。
2. **AI 整理**：系統每 10 分鐘收件，Claude 讀公文，寫好公告標題、內文、分類、公告起迄日，並檢查個資（紅、黃、綠燈）。
3. **審核**：在審核台修改、核准或退回。紅燈的公文預設擋下。
4. **發布**：開著校網後台分頁，公告助手自動填表、上傳檔案、送出，確認校網出現後標成「已發布」。
5. **寄信**（選用）：選了「寄信」的公文，核准後排進「寄信佇列」試算表；裝在學校寄件帳號的「寄信小幫手」每 5 分鐘寄出，附上公文和附件。「公告＋寄信」會等校網上架後才寄，信裡附公告網址。
6. **通知**：處理失敗、公告助手暫停、後台登入過期、核准太久沒發布、寄信失敗，會傳 Telegram（沒設就寄 email）。

## 安全須知（請先讀）

- **套件裡沒有任何金鑰、帳號密碼或個人網址。** 每位老師用自己的 Google 帳號、自己的 API 金鑰，資料各自獨立。
- **API 金鑰、Telegram token、BRIDGE_TOKEN 都是密碼。** 只貼在 Apps Script「專案設定 → 指令碼屬性」，不要寫進程式碼，也不要貼到聊天、Email、文件或 GitHub。
- **不要設定 `RPAGE_USER`、`RPAGE_PASS`。** 系統不需要校網後台帳密，公告助手直接用你已經登入的瀏覽器操作，驗證碼也是你自己輸入。
- **審核台的存取權一定選「只有我自己」。**
- **不要把自己正在用的 Apps Script 專案分享給別人。** 指令碼屬性（含 API 金鑰）可能一起被看到。要分享請用乾淨的範本專案或這個套件。
- **寄信只寄學校網域。** 收件群組只能填 `MAIL_DOMAIN` 的信箱，寄信小幫手寄出前會再檢查一次；一封最多 50 個收件信箱（Google 的上限，一個群組信箱算 1 個）。
- **寄信佇列只給你和寄件帳號編輯。** 寄信小幫手發現多了別人可以編輯，或開成「知道連結的人可以編輯」，就會停止寄信，避免別人借這個帳號寄信。
- **金鑰外流時**：到 console.anthropic.com 停用那把金鑰再建新的；Telegram 對 @BotFather 傳 `/revoke`；BRIDGE_TOKEN 重新執行 `makeBridgeToken`。

## 需要準備

- Google 帳號（建議用學校的 Google Workspace 帳號）。
- Anthropic API 金鑰：到 console.anthropic.com 註冊並設定付款，在「API Keys」按「Create Key」。依用量計費。
- 電腦版 Chrome，安裝 Tampermonkey 擴充功能。
- 校網後台「公告模組」的新增權限。
- （選用）Telegram，用來收通知。
- （選用，寄信用）一個學校 Google Workspace 寄件帳號，例如處室共用信箱，而且有權限寄信給要寄的 Google 群組。

## 安裝步驟

### A. 取得程式（擇一）

- **範本專案（最快）**：打開分享給你的範本連結 → 左側「總覽」（ⓘ 圖示）→ 右上角「建立複本」→ 打開複本，左上角把名稱改成「公文自動公告系統」。做完直接跳到步驟 C。
- **GitHub**：打開存放庫頁面 →「Code」→「Download ZIP」→ 解壓縮。
- **zip 檔**：直接解壓縮。

### B. 建立 Apps Script 專案（用範本建立複本的跳過）

1. 打開 script.google.com →「新專案」，左上角把專案改名成「公文自動公告系統」。
2. 用記事本打開 `1_Code.gs`，全選、複製，貼進「程式碼.gs」，取代原本的內容。
3. 按「檔案」旁的「＋」→「HTML」，檔名打 `Review`（不用打 .html），貼上 `2_Review.html` 的全部內容。
4. 按 Ctrl+S 存檔。

### C. 學校設定（同一所學校的老師跳過）

照下面「不同學校要改的地方」修改 `程式碼.gs` 最上面的 CONFIG，改完存檔。

### D. 設定 API 金鑰

左側齒輪「專案設定」→ 拉到最下面「指令碼屬性」→「新增指令碼屬性」（已經有屬性時要先按「編輯指令碼屬性」）：屬性填 `ANTHROPIC_API_KEY`，值貼上你的金鑰 →「儲存指令碼屬性」。

### E. 執行 setup

1. 回到編輯器，上方函式選單選 `setup`，按「執行」。
2. 第一次執行要授權：選你的帳號 → 畫面出現「Google 尚未驗證這個應用程式」時按「進階」→「前往『公文自動公告系統』（不安全）」→「允許」。這是你自己的程式，所以 Google 會這樣提醒。
3. 執行紀錄會列出建立好的「公文自動公告」資料夾（00_待處理、01_處理中、02_待審核、03_已發布、99_已退回）和「公告佇列」試算表。

### F. 部署審核台

1. 右上角「部署」→「新增部署作業」→ 左邊齒輪選「網頁應用程式」。
2. 說明打 `v1`；執行身分選「我」；誰可以存取選「**只有我自己**」→「部署」，需要的話再授權一次。
3. 複製「網頁應用程式」網址（結尾是 `/exec`），加入書籤：這就是你的審核台。

### G. 產生公告助手的通行碼

1. 函式選 `makeBridgeToken` →「執行」。
2. 函式選 `bridgeInfo` →「執行」。執行紀錄會顯示 Web App 網址和 BRIDGE_TOKEN，下一步要用。

### H. 安裝公告助手

1. 從 Chrome 線上應用程式商店安裝 Tampermonkey。
2. 網址列打 `chrome://extensions` → Tampermonkey 的「詳細資料」→ 打開「允許使用者指令碼」。（有些 Chrome 版本是打開右上角的「開發人員模式」。）
3. 點 Tampermonkey 圖示 →「管理面板」→「＋」新增腳本 → 把預設內容全部刪掉 → 貼上 `3_公告助手.user.js` 的全部內容 → Ctrl+S。
4. 不是達觀的老師：先把第 6 行 `@match` 的網址改成你學校的校網後台，例如 `https://www.xxx.ntpc.edu.tw/platform/*`，再存檔。

### I. 連接公告助手

1. 用同一個 Chrome 先打開一次審核台網址，確認看得到審核台（代表 Google 已登入）。
2. 登入校網後台，進入「公告模組」頁，右下角會出現「公告助手」按鈕。
3. 打開面板，貼上 Web App 網址和 BRIDGE_TOKEN →「儲存設定」。
4. 按「重新整理清單」，沒有出現錯誤就是連上了。

### J. 試跑與啟用

1. 回到 Apps Script，函式選 `installIntakeTrigger` →「執行」，系統開始每 10 分鐘收件。
2. 丟一份可以公開的測試公文 PDF 到「00_待處理」，最慢約 13 分鐘會出現在審核台。
3. 在審核台檢查內容，按「核准，送交發布」。
4. 到後台按公告助手的「試跑：只填表、不送出」，檢查表單內容後按「取消」。
5. 沒問題就勾「核准後自動發布」。審核台頂端出現綠字「公告助手：運作中」，就安裝完成了。

### K. （選用）Telegram 通知

1. 在 Telegram 搜尋 @BotFather，傳 `/newbot`，照指示取名，會拿到一串 token。
2. 指令碼屬性新增 `TELEGRAM_BOT_TOKEN`，值貼上 token。
3. 在 Telegram 打開你剛建的機器人，按「開始」。
4. 函式選 `setupTelegram` →「執行」。Telegram 收到「通知已連上」就完成了。之後可以執行 `testNotify` 測試。

沒設 Telegram 的話，通知會寄 email 給你（或寄到指令碼屬性 `NOTIFY_EMAIL` 填的信箱）。

### L. （選用）寄信功能

先在系統專案設定好，再到寄件帳號裝寄信小幫手。

1. **系統專案**：確認 CONFIG 的 `MAIL_SENDER`（寄件帳號）、`MAIL_DOMAIN`（學校信箱網域）已經改好，見「不同學校要改的地方」。
2. 函式選 `setupMail` →「執行」→ 授權。它會建立「寄信佇列（公文自動公告）」試算表，分享給寄件帳號編輯，並讓寄件帳號可以讀 02_待審核、03_已發布 兩個資料夾（附件要從這裡讀）。
3. **寄件帳號**：用寄件帳號登入 script.google.com →「新專案」→ 改名「寄信小幫手」→ 刪掉預設的 `function myFunction() {}` → 貼上 `4_寄信小幫手.gs` 的全部內容 → Ctrl+S。
4. 不是達觀：把程式上面 `ALLOWED_DOMAIN` 改成你學校的信箱網域，存檔。
5. 函式選 `setup` →「執行」→ 授權。執行紀錄會列出「目前可以編輯寄信佇列的人」，確認只有你和寄件帳號。
6. 函式選 `testSend` →「執行」，寄件帳號會收到一封測試信。
7. 回到審核台重新整理，頂端出現「寄信小幫手：運作中」就完成了。第一封正式信建議先寄給只有自己的群組（做法見「使用方式」的管理群組）。

## 使用方式

**每天**

1. 把公文丟進「00_待處理」，或等系統從信箱收件。
2. 打開審核台，點「待處理」裡的公文，檢查 AI 寫好的內容和個資紅綠燈。
3. 選「發布方式」：公告＋寄信、只有公告、只有寄信。選了寄信，就檢查寄件標題（格式：`發布單位-[發布內容歸類]-內容簡要說明`）、收件群組和信件內文。
4. 按核准。要公告的，確認校網後台分頁開著（公告助手會自動發）；要寄信的，寄信小幫手 5 分鐘內寄出。

**AI 研判「不宜公開到校網」時**

審核台會出現黃色警告和原因，預設「只有寄信」。你確認可以公開的話，勾「我已確認可以公開到校網（解除警告）」，就能改選公告。系統會記下誰在什麼時候解除的。內文出現身分證、手機號碼等個資，或公文有密等，會是紅燈；要按「確認風險，強制送出」並寫原因。

**管理收件群組**

在寄信區按收件群組旁的「管理群組」：

- 可以新增、改名、改信箱、刪除群組。
- 一個群組可以放多個信箱（用逗號、空白或換行分開，最多 50 個），例如「七年級自然老師」放三位老師的信箱。
- 按「儲存群組」後立刻生效。刪掉的群組，已經排進寄信佇列的信照常寄；還在等公告上架的信會寄信失敗，重新勾選後按「重新寄送」。

**寄信出問題**

- 寄信失敗：審核台會標「寄信失敗」並寫原因，改好後按「重新寄送」，或按「不寄了」。
- 「可能已經寄出」：寄信時出錯，不確定有沒有寄出。先到寄件帳號 Gmail 的「寄件備份」確認，沒寄出再按「重新寄送」。

## 不同學校要改的地方

同一所學校（達觀）的老師都不用改。其他學校改下面這幾項：

| 設定 | 在哪個檔案 | 要改成什麼 |
| --- | --- | --- |
| `SCHOOL_NAME` | 程式碼.gs 的 CONFIG | 學校全名，AI 寫公告時會用到 |
| `SITE_URL` | 程式碼.gs 的 CONFIG | 校網網址，例如 `https://www.xxx.ntpc.edu.tw`，結尾不要加 `/` |
| `CATEGORIES` | 程式碼.gs 的 CONFIG | 公告分類，名稱要跟後台的分類一字不差（例如把「達觀新聞」換成你學校的） |
| `RPAGE_GROUPS` | 程式碼.gs 的 CONFIG | 每個分類對應的公告模組代號，找法在下面 |
| `RPAGE_ALSO_POST_TO` | 程式碼.gs 的 CONFIG | 每則公告都要加勾的模組，預設「最新消息」 |
| `ARCHIVE_FOLDERS` | 程式碼.gs 的 CONFIG | 審核台「歷史公文」分頁的資料夾分類，改成你自己習慣的分類名稱 |
| `@match` | 3_公告助手.user.js 第 6 行 | 你學校的校網後台網址加 `/platform/*` |
| `MAIL_SENDER` | 程式碼.gs 的 CONFIG | （寄信用）寄件帳號，寄信小幫手要裝在這個帳號 |
| `MAIL_DOMAIN` | 程式碼.gs 的 CONFIG | （寄信用）學校信箱網域，例如 `xxx.ntpc.edu.tw` |
| `MAIL_GROUPS` | 程式碼.gs 的 CONFIG | （寄信用）預設收件群組。之後在審核台「管理群組」增減就好，不用改程式 |
| `MAIL_UNITS`、`MAIL_TYPES` | 程式碼.gs 的 CONFIG | （寄信用）寄件標題的發布單位簡稱和內容歸類，照你學校的信件規範 |
| `ALLOWED_DOMAIN` | 4_寄信小幫手.gs 上面的 HELPER | （寄信用）跟 `MAIL_DOMAIN` 一樣 |

**找公告模組代號**：後台「公告模組」→「新增資訊」→ 在「選擇所屬公告模組」的勾選框上按右鍵 →「檢查」→ 看 `value="數字"`，那個數字就是代號。

## 常見問題

- **授權時出現「Google 尚未驗證這個應用程式」**：正常，按「進階」→「前往」即可。
- **審核台一直顯示「載入中」**：改過程式後要建立新版本，見「更新到新版本」。
- **後台沒有出現「公告助手」按鈕**：確認 Tampermonkey 已打開「允許使用者指令碼」、`@match` 網址正確，再重新整理後台頁面。
- **公告助手連不上（重新整理清單出現錯誤）**：Web App 網址要是 `/exec` 結尾；Chrome 要登入安裝系統的那個 Google 帳號。同時登入多個 Google 帳號容易出錯，建議用只登入這個帳號的 Chrome 設定檔。
- **審核台頂端顯示「公告助手：還沒有回報」，公文一直停在「待發布」**：公告助手要 1.7 版以上，而且校網後台分頁要開著。另外確認 Tampermonkey 打開了「允許使用者指令碼」（新版 Chrome 一定要開），以及這個 Chrome 登入的是安裝系統的 Google 帳號。
- **審核台顯示「寄信：還沒設定」**：在系統專案執行 `setupMail`。
- **審核台顯示「寄信小幫手：還沒有回報」或「停止寄信」**：到寄件帳號的寄信小幫手專案執行 `setup`，看執行紀錄的原因。最常見的是寄信佇列被分享給別人編輯。
- **寄出了但有人沒收到**：確認寄件帳號在那個 Google 群組有「發布」權限。被群組擋下的信，系統不會知道。
- **函式選單找不到 `testSend`**：`testSend` 在寄信小幫手專案裡，不在系統專案；貼上程式後要先存檔，選單才會更新。
- **公文解析失敗**：確認 `ANTHROPIC_API_KEY` 正確，以及 Anthropic 帳戶還有額度。
- **想暫停收件**：執行 `pauseAll`；要恢復時執行 `installIntakeTrigger`。

## 更新到新版本

1. 用新的 `1_Code.gs`、`2_Review.html` 取代專案裡的舊內容，存檔。指令碼屬性和佇列資料都不受影響。
2. 「部署」→「管理部署作業」→ 鉛筆圖示 →「版本」選「建立新版本」→「部署」。審核台網址不會變。
3. 公告助手：Tampermonkey 管理面板打開腳本，全選貼上新版，存檔。
4. 寄信小幫手：用寄件帳號打開「寄信小幫手」專案，全選貼上新的 `4_寄信小幫手.gs`，存檔。不用重跑 `setup`。
